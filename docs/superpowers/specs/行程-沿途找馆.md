# 行程 · 沿途找馆

> 状态：设计稿，未实现 · 2026-11-15
> 一句话：**你告诉我要去哪儿，我告诉你这一路值得看哪些馆。**

---

## 1. 问题

现在的「行程」是一张**你自己挑好的馆**的清单，问题很多：

- **连不起来**：站点之间画直线，距离也只是直线距离。
- **城市点不了、搜不了**：没有「城市」这一层，只能从馆的详情里一座一座加。
- **没有路线**：只有直线，看不出这一路怎么走。
- **方向反了**：用户心里先有的是出行计划（下个月开车去西安、坐高铁去洛阳），然后才问「这一路有什么该看的」。现在却要用户先自己找好馆，最难的一步留给了用户。

## 2. 新的定位

```
我的出行（城市、路线） ──► 沿途该看的馆（推荐 + 理由） ──► 挑选 ──► 按天排好
```

行程是**找馆的工具**，不是已选馆的展示。

---

## 3. 第一步：输入「我的出行」

先选方式，两种方式的规划单位不同：

| 方式 | 规划单位 | 输入 | 例子 |
|---|---|---|---|
| **自驾** | 一条路线 | 起点、终点、想途经的城市（有顺序） | 北京 → 郑州 → 洛阳 → 西安 |
| **坐车 / 坐飞机** | 一串城市 | 有序的城市，可选每城几天 | 北京（2 天）→ 洛阳（1 天）→ 西安（2 天） |

**怎么加城市**
- 搜索框：城市名、拼音、首字母都能搜。
- 地图：点城市名字直接加入。
- 常用：列出有馆的城市，标出各有几座馆。
- 拖动排序，可删除。

**城市数据**：需要一份**全国地级市及以上的城市表**（约 340 个，含坐标），作为静态数据。因为起点、途经点不一定有馆（比如从石家庄出发），所以不能只用现在有馆的 59 个城市。

---

## 4. 路线：有路线就够，不做导航

**决定（2026-11-15）**：只要在地图上画出这一路的路线、做出「沿途」的感觉，**不接导航 App，也不需要高德 key**。

| 级别 | 服务 | 效果 |
|---|---|---|
| ① | **OSRM**（基于 OpenStreetMap，无需 key，已实测） | 真实道路：北京→洛阳→西安 1174 公里，分段 800 / 373 公里；用时偏保守，只作参考 |
| ② | **直线兜底** | OSRM 不可用时，相邻城市连直线 |

- **调用经过我们的服务器**：结果存进 KV 缓存，同一条路线不重复请求。OSRM 公共服务要求低频使用，缓存后个人工具的用量没有问题。
- 以后如果需要更准的国内路线，可以再接高德路径规划，接口形式不变。
- **坐标**：OSRM 用国际标准坐标（WGS-84），我们的地图底图是高德坐标（GCJ-02），画线前要转换。项目里已经有现成的转换算法。
- **坐车 / 坐飞机模式不需要道路路线**：城市之间画一条示意弧线，同时给出距离和建议的交通方式（见第 6 节）。

## 5. 第二步：沿途该看的馆

### 5.1 找馆的范围

| 方式 | 范围 | 默认值，可调 |
|---|---|---|
| 自驾 | 路线两侧的走廊；标出每座馆**要绕路多少公里** | 两侧 30 公里，可选 30 / 60 / 120 |
| 坐车 / 坐飞机 | 每个城市中心周围 | 30 公里，可选 15 / 30 / 60 |

### 5.2 为什么值得去：每座馆一句话

| 标签 | 含义 | 依据 | 例子 |
|---|---|---|---|
| **必看** | 不来可惜 | 世遗、一级馆、有镇馆之宝 | 「陕西历史博物馆 · 镇馆之宝 唐三彩骆驼载乐俑」 |
| **补你的空层** | 你还没集到这个朝代 | 你的集章 | 「补上三国」 |
| **接得上** | 和你已集的朝代连成线 | 你的集章 | 「东汉之后接三国」 |
| **原址** | 就建在历史现场 | 原址数据 | 「龙门石窟就是北魏的现场」 |
| **顺路** | 绕路很少 | 绕路公里数 | 「几乎不绕路，+4 公里」 |

- **排序**：必看 > 补空层、接得上 > 原址 > 顺路。没登录、也没集章的新用户，只看「必看」和「顺路」。
- **复用现有逻辑**：「地层账本 → 附近可补」里已经有补空层、接得上的计算，只是锚点从「已选的馆」换成「城市或路线」。

### 5.3 怎么呈现

- **按行程先后分组**：自驾按路线顺序；坐车按城市，城市内按顺路排。
- **地图**：画出路线和走廊；推荐的馆按标签用不同颜色；点任意一座馆，可以「加入这一趟」。
- **这一趟的历史线**：根据推荐的馆和你的集章，给出一句话主题，比如「这一趟能走通周、秦、汉、唐」「补上之后，你的地层从东汉一直连到唐」。

## 6. 第三步：挑选、排天、出发

**挑选**：勾选想去的馆。超过每天 2 到 3 座的建议量时，提醒「这一天可能看不完」。

**按天排**：
- 自驾：按路线顺序分天。
- 坐车：按城市和天数分。
- 想细排，可以「让讲解员排行程」（现有功能），把出行方式、城市、天数、挑好的馆一起交给它。

**城市之间的交通**（仅坐车 / 坐飞机模式）：

| 距离 | 建议 | 估算用时 |
|---|---|---|
| < 150 公里 | 高铁或大巴 | 约 1 小时 |
| 150 – 1200 公里 | 高铁 | 距离 ÷ 250 公里/小时 + 1 小时 |
| > 1200 公里 | 飞机，或高铁卧铺 | 飞行约 2–3 小时，加上往返机场 |

订票暂不接入：12306 没有开放接口。最多提供一个「查车票」的外链。

## 7. 数据与存储

```
trip = {
  mode: 'drive' | 'transit',
  cities: [{ id, name, lat, lng, days? }],   // 有序
  radiusKm,                                   // 走廊宽度或城市半径
  picks: [museumId],                          // 挑中的馆
  route?: { provider, distanceKm, durationH, legs, polyline }   // 自驾，来自缓存
}
```

- 存在本机（localStorage）；登录用户以后可以同步到服务器。
- **旧行程迁移**：现在的行程（一串馆）转换成「坐车模式 + 由这些馆推出的城市 + picks」，不丢数据。
- 新增服务器接口：`/api/route?points=…`，先试 OSRM，失败退回直线，结果缓存到 KV。

## 8. 手机

- 行程面板改成**底部抽屉**，地图始终露出来；抽屉有三种高度：收起、半屏、全屏。
- 城市搜索框的字号保持 16px，避免 iOS 输入时自动放大。

## 9. 和其他功能的关系

- **地层账本、附近可补**：推荐逻辑共用。「沿行程」的锚点改成新的城市或路线。
- **打卡**：这一趟回来以后，可以看到「这一路你集到了哪些朝代」。
- **历史的音符**：成长策略落地后，推荐理由里可以加上音乐收益（比如「补上三国，曲子在这里不再断开」），见《历史的音符-打卡成长策略》。

## 10. 分期

| 期 | 内容 | 依赖 |
|---|---|---|
| 一 | 坐车模式：城市表、城市搜索、地图点城市、按城市推荐（必看、补空层、接得上）、挑选、按天排；旧行程迁移；手机底部抽屉 | 无 |
| 二 | 自驾模式：`/api/route`（OSRM 加直线兜底）、真实路线、走廊找馆、绕路距离 | 无 |
| 三 | 讲解员排行程接入新的数据；这一趟的回顾；音乐收益（随成长策略） | — |
