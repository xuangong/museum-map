# 「历史的音符」成长系统 · 设计方案

> 状态：设计稿，未实现 · 2026-11-14
> 目标：馆藏扩到 300–500 座以后，**每多打一座卡，曲子都还能听出变化**；并且系统要能告诉用户「下一座去哪儿，曲子会变成什么样」。

---

## 0. 为什么要做：现在的问题

两位真实用户的数据：

| 用户 | 打卡 | 覆盖朝代 | 乐器六类 | 名曲朝代 | 结论 |
|---|---|---|---|---|---|
| 马晓雨 | 43 | 20/20 | 齐 | 8/8 | 已到顶 |
| 1508069247 | 15 | 19/20（缺辽） | 齐 | 8/8 | 已到顶 |

一座馆平均关联约 3 个朝代，所以**认真打卡的人十几座馆就把曲子长满了**，之后几百座馆不再带来任何音乐上的变化，只剩每次演奏的随机差异。

现在的成长只看「集了哪些朝代」这一个维度。馆的**级别、是不是原址、在哪个地方、有什么特色**，以及**朝代之间连不连得上、每个朝代打得有多深**，这些都没有用上。偏偏这些维度在 300–500 座馆的规模下是最有区分度的。

## 1. 现在的音乐是怎么做的（设计的基础）

后面所有成长都建立在这套已经能稳定和谐的框架上：

| 机制 | 现状 |
|---|---|
| 骨架 | 一首写好的五声主曲，5 个乐句、20 小节；乐句之间鱼咬尾；商→宫收尾 |
| 织体 | 丝竹式支声复调：领奏加花；弹拨低八度弹骨干音；拉弦低八度连奏；吹管高八度长音；古琴强拍和句尾泛音；钟磬、鼓只标乐句的起落；最后全体齐奏收在主音上 |
| 乐器 | 每个朝代一件乐器，尽量取自真实馆藏（如曾侯乙编钟、贾湖骨笛）；共六类乐器，每类同时只响一件 |
| 名曲 | 11 首真实古谱片段（流水、梅花三弄、阳关三叠……），按朝代插入，每次最多奏 4 首，支持偏音 4 和 7 |
| 随打卡生长 | 朝代数决定曲子长度（1→6 句）；同类乐器数和同一朝代的馆数决定加花程度（共 3 档） |
| 每次演奏都不同 | 调式（宫商角徵羽）、调高、速度、换头、加花落点、领奏乐器、选哪几首名曲 |
| 声画同步 | 音符排在音频时钟上；琴弦按同一时钟振动；地层随演奏高亮；字幕显示「此声取自……」和名曲典故 |

**设计原则：成长只「加东西」，不动骨架。**新内容一律进现有框架（五声音阶、支声复调、鱼咬尾、名曲严格按原谱），保证打得再多也不会把曲子打乱。

## 2. 两条成长线

打卡带来的成长分两条线，每座馆可能同时推动两条。

```
                    ┌──────────── 丰富性（广度）────────────┐
                    │  朝代广度 · 地域广度 · 类型广度 · 特色广度 │
  一次打卡 ────────►│                                       │──► 曲子变「多」：更多乐器、名曲、色彩
                    └───────────────────────────────────────┘
                    ┌──────────── 连续性（深度）────────────┐
                    │  朝代连线 · 断代成段 · 一朝深度 · 原址与都城 │
                    │                                       │──► 曲子变「顺」变「长」：衔接、乐章、套曲
                    └───────────────────────────────────────┘
```

- **丰富性**回答：你的曲子里有多少种声音？
- **连续性**回答：你的曲子能不能从头到尾、一脉相承地奏下来？

两条线各有一个可见的进度，最后合成「我的曲谱」。

## 3. 维度 → 音乐：每个维度让用户听到什么

这一节是方案的核心：**每个数据维度都对应一个听得出来的音乐变化。**用户不需要理解分数，只要听得出「这座馆让我的曲子多了什么」。

### 3.1 丰富性一：朝代广度（已有，保留）

| 数据 | 音乐 |
|---|---|
| 集到某个朝代 | 这个朝代的乐器加入合奏；有名曲的朝代可能插入名曲 |
| 集到的朝代数 | 曲子长度：1 句 → 5 句 → 加尾声 |

### 3.2 丰富性二：馆的类型（新增）

不同类型的馆贡献**不同性质的声音**，鼓励用户什么类型都去，而不是只刷一种。

| 馆的类型 | 音乐里的角色 | 寓意 |
|---|---|---|
| **世界文化遗产** | 解锁「金石之声」：乐句开头一记大钟、特磬，像礼乐开场 | 世遗是全人类的历史坐标，声音最庄重 |
| **全国重点文物保护单位** | 解锁这个朝代的「古琴泛音」声部：句尾的一声泛音 | 古建、遗址往往就是原物，用泛音这种「从琴身里浮出来的声音」表示 |
| **国家一级博物馆** | 解锁这个朝代名曲的「下一句」（见 3.6） | 一级馆藏品体系完整，承担名曲 |
| **二级馆、专题馆** | 这个朝代的加花再升一档，或者打开一个「特色音色」（见 3.4） | 小馆有专长，补的是细节和色彩 |

> 数据：现有 `tiers` 把世遗和国保合在 `heritage-site` 一类，需要拆开（`level` 文本里已经写明，可以正则区分）。

### 3.3 丰富性三：地域广度（新增，「地方风格」）

把全国分成 **8 个音乐地域**，每个地域对应一种传统乐种的味道。在某个地域打卡，就解锁它的地方风格。每次演奏随机带上一种已解锁的风格：

| 地域 | 乐种参考 | 带来的变化（都在现有框架里实现） |
|---|---|---|
| 江南（沪苏浙皖） | 江南丝竹 | 加花更密、更柔；拉弦用二胡音色 |
| 岭南（粤桂琼港澳） | 广东音乐 | 高胡音色；偶尔用「乙反」：在 4、7 上加偏音（引擎已支持） |
| 闽台 | 南音 | 洞箫加琵琶，速度更慢，句尾拖腔 |
| 西北（陕甘宁青新） | 秦腔、花儿 | 板胡音色；「苦音」：降 7、升 4；节奏更硬朗 |
| 华北（京津冀晋鲁豫） | 山西八大套、鼓吹 | 唢呐、笙；鼓的声部加重 |
| 西南（川渝云贵藏） | 四川清音、洞经音乐 | 竹笛加三弦；节奏更跳跃 |
| 华中（鄂湘赣） | 楚地编钟、湖南花鼓 | 钟磬声部加强；更明亮 |
| 东北、内蒙古 | 长调、马头琴 | 马头琴音色；悠长的散板拖腔 |

- 地域按馆的 `location` 解析出省份，再归入大区。
- 「地方风格」只改音色、加花方式和少量偏音，**不改旋律骨架**，所以和谐有保证。
- 需要新增的音色：二胡、高胡、板胡、唢呐、笙、三弦、马头琴，都能用现有的弓弦和吹管合成器调出来。

### 3.4 丰富性四：特色（新增，「乐器图鉴」和「专题音色」）

**乐器图鉴（最强的一条）**
每个朝代的乐器出处都是一件真实文物（`src/data/era-voices.ts`）：

- **没去过出处那座馆**：这个朝代用「示意」版音色，偏素、偏薄。
- **去过出处那座馆**：换成「真声」版，泛音更丰富、余音更长；字幕变成「你在湖北省博物馆见过它 · 曾侯乙编钟」。

现在有 15 件乐器出处，馆扩到 300–500 座以后，可以让每个朝代都有 2–3 件候选乐器。图鉴的成长空间就是「集齐 N 件真乐器」。

**专题音色**
给馆加「特色」标签：青铜、玉器、陶瓷、书画、石窟造像、古建、丝路、宗教、民族、科技。每类特色对应一个点缀音色，在乐句间隙出现一下：

| 特色 | 点缀 |
|---|---|
| 青铜 | 编钟余音 |
| 石窟造像 | 磬、木鱼 |
| 丝路 | 驼铃、琵琶轮指 |
| 陶瓷 | 瓷瓯（水盏击打） |
| 书画 | 古琴走手音 |
| 宗教 | 云锣、钹 |
| 民族 | 马头琴、芦笙 |
| 科技、天文 | 铜壶滴漏的「嗒」声，做节拍点缀 |

> 数据：馆需要新增 `features` 标签。可由 `specialty`、`treasures`、`artifacts` 自动打初稿，再人工审核（同 44 馆补关联的做法）。

### 3.5 连续性一：朝代连线（新增，「鱼咬尾」听得见）

现在没集到的朝代会被直接跳过，听不出缺了什么。改成：

- **连上的朝代**：相邻两个已集朝代之间，鱼咬尾衔接，乐器交接时「嵌挡」一个过门，听起来一气呵成。
- **断开的地方**：中间有没集到的朝代，就出现一段 **「断弦」**：音乐停半拍，然后从散板重新起。用户能听出这里断了，字幕提示「三国 · 尚未集到，曲子在这里断开」。
- **补上一个朝代**：断弦变成鱼咬尾。这是最直接的「补卡就能听到变化」。

### 3.6 连续性二：一朝深度（新增，名曲越奏越长）

同一个朝代打的馆越多，这个朝代的名曲奏得越完整：

| 该朝代打卡数 | 名曲 |
|---|---|
| 1 | 一句（现状） |
| 3 | 两句（比如《阳关三叠》接上「客舍青青柳色新」） |
| 5 | 解锁该朝代的第二首名曲 |
| 8 | 名曲的「叠」：同一句再奏一遍加花版（借《阳关三叠》「三叠」的做法） |
| 12 | 该朝代的名曲「全段」：一整段原谱 |

需要从原谱多读几句，方法已经验证过：国琴网等来源的刻印简谱，逐张肉眼核对。

### 3.7 连续性三：断代成段（新增，「乐章」）

把 20 个朝代分成 6 个历史段落。一段之内全部集齐，这一段就成为一个 **乐章**，由那个时代真实的音乐形态来奏：

| 段 | 朝代 | 乐章形态 | 听起来 |
|---|---|---|---|
| 先秦 | 远古、夏、商、西周、东周 | **金石雅乐** | 编钟、编磬为主，庄重缓慢，骨笛起头 |
| 秦汉 | 秦、西汉、东汉 | **鼓吹** | 鼓和管领奏，节奏铿锵 |
| 魏晋南北朝 | 三国、两晋、南北朝 | **琴曲** | 古琴独领，散板起，泛音收，《广陵散》《梅花三弄》的气质 |
| 隋唐五代 | 隋、唐、五代 | **燕乐大曲** | 按「散序—中序—破」：先自由，再舒缓歌唱，最后转快 |
| 宋辽金元 | 宋、辽、金、元 | **词调与胡乐** | 洞箫唱词调，胡琴应和，南北交融 |
| 明清 | 明、清 | **丝竹** | 江南丝竹的满庭芳式合奏，加花最繁 |

- 段没集齐时，这些朝代按现在的方式奏。
- 段集齐时，这一段改用乐章形态奏，乐章之间用鱼咬尾连接。
- 全部 6 段集齐，整首曲子成为 **「大套」**：按传统大套的「散—慢—中—快—散」速度弧线，从远古的散板起，到明清的快板，再回到「今」的散板齐奏。这是整个成长系统的终点。

### 3.8 连续性四：原址与都城（新增，「此地即彼时」）

- **原址**：馆就建在那个朝代的现场（数据里已有 127 对）。去过原址，这个朝代的乐句**多一层空间感**：更长的混响，像在遗址里回荡。字幕写「你站在了历史站过的地方」。
- **都城**：每个朝代的都城迁徙线上，馆打得越全，这个朝代在时空图里的都城连线越亮。音乐上，都城迁徙的方向变成旋律的走向，比如迁都往南，乐句就往下走。

## 4. 两个进度条：「广」和「续」

不给用户看复杂的分数，只给两个看得懂的进度，加上一个总称号。

### 4.1 「广」（丰富性）

| 子项 | 满值 | 说明 |
|---|---|---|
| 朝代 | 20 | 集到的朝代数 |
| 地域 | 8 | 8 个音乐地域 |
| 类型 | 4 | 世遗、国保、一级馆、其他 |
| 真乐器 | 15→可扩 | 乐器图鉴 |
| 特色 | 10 | 专题音色 |

### 4.2 「续」（连续性）

| 子项 | 满值 | 说明 |
|---|---|---|
| 最长连线 | 20 | 最长的连续朝代链 |
| 乐章 | 6 | 集齐的断代段 |
| 名曲深度 | 每朝 5 档 | 见 3.6 |
| 原址 | 20 | 去过原址的朝代数 |

### 4.3 称号（借乐师的成长）

| 称号 | 条件（示意，需用真实分布校准） | 曲子大概的样子 |
|---|---|---|
| 闻声 | 第 1 座 | 一根弦，一句引子 |
| 识谱 | 5 座 | 小合奏，第一首名曲 |
| 抚琴 | 朝代 ≥ 12，且有 1 个乐章 | 完整的五句，第一个乐章 |
| 合奏 | 3 个乐章，地域 ≥ 4 | 有地方风格，有乐章 |
| 成套 | 6 个乐章 | 大套「散—慢—中—快—散」 |
| 大成 | 成套，地域 8，图鉴过半，名曲深度过半 | 每次演奏都很不一样，深度用户的终点 |

要让成长拉得够长：按 300–500 座馆估算，「成套」大约要 40–80 座且分布均衡；「大成」要 150 座以上，并且走过全国。具体门槛等数据扩充后用模拟校准（方法同之前的 4000 次随机抽样）。

## 5. 指导用户下一步：「去这座馆，曲子会变成这样」

光有进度不够，要告诉用户**下一座去哪、去了能听到什么**。

### 5.1 每座候选馆的「音乐收益」

对每座没去过的馆，算出它能带来的变化，用**音乐语言**而不是分数描述：

| 收益 | 示例文案 |
|---|---|
| 补断弦 | 「补上三国：东汉和两晋之间不再断开，《胡笳十八拍》会直接接上《梅花三弄》」 |
| 成乐章 | 「再集金：宋辽金元成为一个乐章，洞箫和胡琴的词调段落」 |
| 名曲加句 | 「唐代再打一座：《阳关三叠》接上『客舍青青柳色新』」 |
| 真乐器 | 「去湖北省博物馆：南北朝的编钟换成曾侯乙编钟的真声」 |
| 新地域 | 「第一次来岭南：解锁广东音乐风格」 |
| 新类型 | 「这是世界遗产：解锁乐句开头的金石之声」 |
| 原址 | 「龙门石窟就是北魏的现场：南北朝的乐句会有遗址回响」 |

排序：先算每座馆在各项上的收益，乘以权重；断弦和乐章的权重最高，因为连续性最难得。再结合距离，复用现在的「附近可补」：当前位置、某个城市、沿行程。

### 5.2 「先听一听」

每条推荐带一个 **试听按钮**：用 `renderTune` 在本地渲染「加上这座馆以后」的曲子，和现在的对比着听。
这在技术上已经可行，`renderTune(F, {eras, seed})` 能离线渲染任意组合。听过之后再决定去不去，激励最直接。

### 5.3 放在哪里

- **「我的曲谱」页**（新）：两个进度条、称号、已解锁的乐器图鉴、名曲、乐章、地方风格，以及三条下一步推荐。
- **「地层账本 / 附近可补」**（已有）：每座候选馆后面加一行音乐收益，比如「♪ 补断弦」「♪ 名曲加句」。
- **演奏中**：断弦处的字幕直接给出补卡建议，比如「三国 · 尚未集到 · 离你最近的是成都武侯祠博物馆」。
- **打卡成功的瞬间**：立刻奏出「这一座给曲子带来的变化」，比如新乐器入场的那一句，或者断弦被接上的那一下。

## 6. 需要新增的音乐内容

| 内容 | 用途 | 来源和难度 |
|---|---|---|
| 名曲后续乐句（每首 +1～3 句） | 一朝深度 | 从已找到的原谱继续读，难度低 |
| 更多名曲（每朝 2–3 首） | 一朝深度、多样性 | 国琴网等刻印简谱，难度中 |
| 6 种乐章形态 | 断代成段 | 用现有织体规则写编配规则（雅乐、鼓吹、琴曲、大曲、词调、丝竹），不需要外部谱，难度中 |
| 大套速度弧线 | 终点 | 编配规则，难度低 |
| 散板与断弦 | 连续性 | 编配规则，难度低 |
| 8 种地方风格 | 地域 | 音色加加花规则；乙反、苦音用现有偏音机制，难度中 |
| 新音色（二胡、高胡、板胡、唢呐、笙、三弦、马头琴、云锣、木鱼、驼铃、瓷瓯） | 地域、特色 | 合成器调参，难度中 |
| 真声和示意两版乐器 | 乐器图鉴 | 同一乐器两组参数，难度低 |

**原则不变**：旋律只用有可靠记谱的古曲；有版权的现代作品（如现代版《敕勒歌》、霓裳的现代复原）不用。

## 7. 数据准备

| 数据 | 现状 | 需要做 |
|---|---|---|
| 馆的类型 | `tiers`：一级 82、世遗或国保 39、二级 7、其他 13 | 把世遗和国保拆开 |
| 地域 | `location` 文本、`city` | 解析省份，归入 8 个大区 |
| 特色 | 无 | 新增 `features`，自动打初稿再人工审核 |
| 朝代关联 | 每馆至少 1 个（有守卫测试） | 扩充时继续保证；区分核心推荐和相关 |

## 9. 分期建议

| 期 | 内容 | 为什么这个顺序 |
|---|---|---|
| 一 | 数据：拆分世遗和国保、解析地域、给特色打标签；名曲补后续乐句 | 后面所有功能都依赖这些数据 |
| 二 | 连续性：断弦和鱼咬尾、一朝深度、断代乐章（先做 2 个乐章验证） | 用户最容易感知，最能带动补卡 |
| 三 | 「我的曲谱」页、下一步推荐、试听对比 | 让成长看得见、找得到 |
| 四 | 丰富性：乐器图鉴真声、类型角色、专题音色 | 需要新音色和标签数据 |
| 五 | 地方风格、大套、称号门槛校准 | 需要扩充后的真实数据来校准 |

每一期都可以单独上线，单独试听验证。

## 10. 风险和约束

- **音乐质量**：新乐章和地方风格是编配规则，不是现成的谱，需要像这次一样反复试听调整。每期都要渲染试听文件，请人工确认。
- **游戏化过度**：语气要是「同好之间的分享」，不是刷任务。文案强调「听见」和「补上」，不用「任务」「积分」这类字眼。不要亲子口吻。
- **数据工作量**：300–500 座馆的标签和关联是最大成本，必须用「自动初稿加人工审核」的流程，不能全靠手写。
- **版权**：只用有可靠来源的古谱；现代作品只提曲名和典故。
- **门槛校准**：所有数字门槛都要等扩充后，用真实分布再模拟校准一次，避免太快到顶，也避免太难达到。
